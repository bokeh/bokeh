4.0.0
=====

Bokeh version ``4.0.0`` is a major milestone of the Bokeh project.

New features
------------

* Added explicit immediate delivery and configurable throttling, debouncing,
  and committed-only delivery to ``Model.on_change()`` and
  ``Model.js_on_change()`` callbacks.
* Expanded :class:`~bokeh.models.Markdown` with syntax highlighting, footnotes,
  heading anchors, admonitions, definition lists, collapsible sections,
  embedded Bokeh models, rendering options, and ``_repr_markdown_()`` support.
* Added :class:`~bokeh.models.ScaledTicker` and
  :class:`~bokeh.models.ScaledTickFormatter` for selecting and formatting ticks
  with a scale and configurable origin. They support repeated prefixes and
  units, symbolic origin labels, fractional coefficients, and TeX or MathML
  decorations without requiring fixed tick locations or custom JavaScript.
* Added :class:`~bokeh.models.SITickFormatter` for displaying values with a
  fixed or automatically selected SI prefix and a shared unit.
* Added support for bracketed IPv6 addresses, such as ``[::1]:5006``, in the
  Bokeh server's WebSocket origin allowlist, including equivalent address
  spellings. ASGI origin entries use the same validation and default port as
  ``Server``.
* Added ``label`` property to :class:`~bokeh.models.Tool`, allowing to change
  the name of a tool displayed in the user interface, e.g. in a plot's context
  menu (:bokeh-issue:`15553`).
* Redesigned slider widgets for better visual appeal and easier theming (:bokeh-pull:`13551`)
* Added :class:`~bokeh.models.IndexedStackColorMapper` for ``ImageStack``
  glyphs. It color maps the 2D array selected by ``index`` with a
  ``slice_color_mapper``, scanning just that array or, with
  ``scan_together=True``, the whole stack as one data set. Scan results are
  cached per array, so changing ``index`` doesn't rescan data that has already
  been scanned (:bokeh-issue:`13898`).
* Added support for ``figure(tools=None)`` (and ``gmap(..., tools=None)``),
  which creates a plot without any tools and without the toolbar, i.e. it is
  a shorthand for ``tools=[]`` with ``toolbar_location=None``. BokehJS'
  ``figure()`` API supports the equivalent ``tools: null``
  (:bokeh-issue:`15747`).
* Reduced verboseness of server debug logs (:bokeh-pull:`13038`)
* Bokeh properties are now typed for static type checkers. Accessing a
  property on a model gives the type of its value, e.g. ``int | None`` for
  ``Nullable(Int)``, ``list[Renderer]`` for ``List(Instance(Renderer))`` or
  a ``Literal`` union for ``Enum(...)``, and accessing it on a model class
  gives a ``PropertyDescriptor``. Assignments are checked as well, and may
  accept more types than values have, e.g. ``list[Row]`` can be assigned to
  ``List(Instance(UIElement))``, because assignments to lists, sets and
  dicts are typed as ``Sequence``, ``AbstractSet`` and ``Mapping``
  respectively (:bokeh-issue:`14814`), values accepted by ``.accepts()``,
  e.g. strings by ``Plot.title``, are accepted, and ``Readonly`` properties
  can't be assigned to (:bokeh-issue:`15760`).

Removals
--------

* Removed support for Python 3.12. Bokeh now requires Python 3.13 or newer.

* Removed the slider and spinner ``value_throttled`` properties. Configure
  committed delivery when registering a callback on ``value``, for example
  ``widget.on_change("value", callback, policy=Committed())``.
* Removed ``output_notebook()``, ``push_notebook()``, the notebook hook
  registration APIs (including ``load_notebook()``, ``show_app()``,
  ``destroy_server()``, and ``get_comms()``), ``CommsHandle``, and
  ``bokeh.io.output``. Notebook display is now
  automatic in supported kernels. ``show(model)`` returns a connected handle
  whose updates are sent automatically.
* Removed the ``browser``, ``new``, ``notebook_handle``, and ``notebook_url``
  arguments from ``show()``. Use ``save()`` for explicit file output and pass
  notebook application and proxy options to ``serve()``.
* Removed one-step ``show(application)`` and ``show(modify_document)`` server
  creation. Start a managed notebook application with ``app = serve(...)``,
  display it with ``show(app)``, and stop it explicitly with ``app.stop()``.
* Removed the legacy notebook templates ``AUTOLOAD_NB_JS``, ``DOC_NB_JS``,
  ``NOTEBOOK_LOAD``, and ``ROOT_DIV``, together with the BokehJS
  ``embed_items_notebook`` and ``kernels`` notebook integration APIs.
* The separately installed ``jupyter_bokeh`` extension is no longer used by
  Bokeh 4.0 and can be uninstalled after upgrading.

* Removed ``DataCube`` and its supporting grouping and aggregation models. For
  hierarchical tables, use Panel's ``Tabulator`` widget. Bokeh-only
  applications can use ``DataTable`` with pre-aggregated data. See
  :ref:`ug_topics_hierarchical` for migration guidance.

* Removed the ``Arrow`` annotation model. Replace
  ``plot.add_layout(Arrow(x_start=..., y_start=..., x_end=..., y_end=...))``
  with ``renderer = plot.arrow(x_start=..., y_start=..., x_end=..., y_end=...)``.
  The returned ``GlyphRenderer`` draws decorated segments. Change shaft
  properties on ``renderer.glyph`` and head properties on its decorations.
  Existing ``OpenHead``, ``NormalHead``, ``VeeHead``, and ``TeeHead`` models
  remain available. Endpoints use data coordinates. Head sizes and decoration
  insets use screen pixels. See :ref:`ug_basic_annotations_arrows` for examples.

* Removed the ``Whisker`` annotation model. Replace
  ``plot.add_layout(Whisker(base=..., lower=..., upper=..., source=...))``
  with ``plot.whisker(base=..., lower=..., upper=..., source=...)``.
  The helper returns a ``Segment`` glyph renderer, with support for glyph
  selection, inspection, and legends. Its endpoints use data coordinates and
  participate in automatic ranging like other segments. Set ``cap_size`` to
  control the tee width in screen pixels. Use ``plot.arrow()`` for custom endpoint
  heads.
  See :ref:`ug_basic_annotations_whiskers` for an example.

* Removed ``bar_color`` and ``direction`` properties from slider widgets
  (:bokeh-pull:`13551`). Use stylesheets to change the color of a slider's
  bar, e.g. ``Slider(..., stylesheets=[InlineStyleSheet(css=".bk-span { background-color: red; }")])``.

* BokehJS no longer depends on noUiSlider. Custom stylesheets that target
  ``.noUi-*`` classes must be updated to target the new slider elements
  (``.bk-track``, ``.bk-span``, ``.bk-handle`` and ``.bk-tooltip``).

* Removed the BokehJS ``Bokeh.Charts`` API, including ``Bokeh.Charts.pie()``
  and ``Bokeh.Charts.bar()``. Use ``Bokeh.Plotting`` instead, e.g.
  ``fig.annular_wedge()`` or ``fig.wedge()`` for pie and donut charts, and
  ``fig.hbar()`` or ``fig.vbar()`` for bar charts.

API changes
-----------

* Generic property base classes and ``Value`` now default their type parameter
  to ``Any`` when it is omitted. Explicit type arguments and constructor
  inference continue to preserve more specific types.

* ``Property`` and its subclasses are now generic in two type parameters,
  the type of values of a property and the type of values that can be
  assigned to it, e.g. ``Property[list[int], Sequence[int]]``. The second
  one defaults to the first one, so e.g. ``Property[int]`` is still valid.
  Generic subclasses of properties must list both type arguments in their
  base classes, e.g. ``class MyProp[G, S](SingleParameterizedProperty[G, S])``,
  because Python doesn't substitute defaults of type parameters that refer
  to other type parameters at runtime (:bokeh-issue:`15760`).

* Default values of properties are now checked by type checkers against
  the types of values that can be assigned to properties. Callable defaults,
  e.g. ``lambda: []`` or ``InstanceDefault(Model)``, are accepted as well.

* Overrides of properties in derived models should now be named after the
  overridden property prefixed with an underscore, e.g.
  ``_width = Override(default=600)`` to override ``width``. This way the
  property isn't redefined, so type checkers retain its type. Optionally,
  the overridden property can be given, e.g.
  ``_width = Override(LayoutDOM.width, default=600)``, to allow type checkers
  to verify the type of the default value. Overrides named exactly like
  properties continue to work (:bokeh-issue:`15760`).

* Inferring literal types of enumerations, e.g. of ``Enum(Location)``,
  relies on ``TypeForm`` (PEP 747). With pyright, this requires version
  1.1.414 or newer. Earlier versions infer such types as ``Unknown``.

* ``ticker`` and ``formatter`` of all axes are now typed as ``Ticker`` and
  ``TickFormatter``, instead of the types of their defaults, e.g.
  ``BasicTicker`` for ``LinearAxis``. This way type checkers accept e.g.
  ``LinearAxis(ticker=FixedTicker(...))``, but code reading attributes
  specific to a ticker or a formatter, e.g. ``axis.ticker.desired_num_ticks``,
  needs to narrow their types first, e.g. with ``isinstance()``.

* Use ``GlyphRenderer.add_path_marking()`` to add a marking at a named or
  fractional position. In Python, call ``renderer.add_path_marking(head, at="end")``.
  In BokehJS, pass ``{at: "end"}`` as the second argument. A field can supply
  one list of fractions per path. Only named start and end positions accept
  an ``inset``.

* ``GlyphRenderer.add_arrowheads()`` places arrowheads at named path nodes or
  fractional positions, including positions supplied by a source column.

* ``PathPlacement``
  places a graphical marking at named or fractional path positions. Its
  ``positions`` property can also reference a source column of fractional lists.

* Sliders no longer default to ``width=300``. The default size is now set
  in CSS and can be changed with the ``--default-size`` CSS variable.

* In BokehJS, ``OrientedControl`` now derives from ``Widget`` instead of
  ``Control``, and ``Control`` is deprecated. ``BBox.relativize()`` now takes
  and returns an ``{x, y}`` object instead of separate coordinates.

* ``ColorMapper`` no longer has ``palette`` and ``nan_color``. They moved to
  the new :class:`~bokeh.models.PaletteMixin`, which ``CategoricalColorMapper``,
  ``ContinuousColorMapper`` and ``WeightedStackColorMapper`` include, so code
  using those mappers is unaffected. Custom color mappers that subclass
  ``ColorMapper`` directly need to include ``PaletteMixin`` (in Python) or
  define ``palette`` and ``nan_color`` themselves, and in BokehJS implement
  ``_palette()`` and ``_colors()``. They also need a ``display_mapper`` getter
  there, usually returning ``this``. BokehJS code that uses ``palette`` through
  a plain ``ColorMapper``, e.g. ``color_bar.color_mapper.palette``, can get it
  from ``color_bar.color_mapper.display_mapper.palette`` (:bokeh-issue:`13898`).

* Property validation failures now raise ``ValidationError``, a subclass
  of the new ``PropertyError`` base class, which itself derives from
  ``ValueError``. Both are available from ``bokeh.core.properties``. Existing
  code catching ``ValueError`` is unaffected.

Bug fixes
---------

* Fixed property validation and warning suppression leaking between concurrent sessions (:bokeh-pull:`15548`).
