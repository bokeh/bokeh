.. _release-4-0-0:

4.0.0
=====

Bokeh version ``4.0.0`` is a major milestone of the Bokeh project.

New features
------------

* Added :class:`~bokeh.models.ScaledTicker` and
  :class:`~bokeh.models.ScaledTickFormatter` for selecting and formatting ticks
  with a scale and configurable origin. They support repeated prefixes and
  units, symbolic origin labels, fractional coefficients, and TeX or MathML
  decorations without requiring fixed tick locations or custom JavaScript.
* Added :class:`~bokeh.models.SITickFormatter` for displaying values with a
  fixed or automatically selected SI prefix and a shared unit.

Removals
--------

* Removed ``output_notebook()``, ``push_notebook()``, the notebook hook
  registration APIs (including ``load_notebook()``, ``show_app()``,
  ``destroy_server()``, and ``get_comms()``), ``CommsHandle``, and
  ``bokeh.io.output``. Notebook display is now
  automatic in supported kernels. ``show(model)`` returns a connected handle
  whose updates are sent automatically.
* Removed the ``browser``, ``new``, ``notebook_handle``, and ``notebook_url``
  arguments from ``show()``. Use ``save()`` for explicit file output and pass
  notebook application and proxy options to ``serve()``.
* Removed one-step ``show(application)`` and ``show(modify_document)`` server
  creation. Start a managed notebook application with ``app = serve(...)``,
  display it with ``show(app)``, and stop it explicitly with ``app.stop()``.
* Removed the legacy notebook templates ``AUTOLOAD_NB_JS``, ``DOC_NB_JS``,
  ``NOTEBOOK_LOAD``, and ``ROOT_DIV``, together with the BokehJS
  ``embed_items_notebook`` and ``kernels`` notebook integration APIs.
* The separately installed ``jupyter_bokeh`` extension is no longer used by
  Bokeh 4.0 and can be uninstalled after upgrading.

* Removed ``DataCube`` and its supporting grouping and aggregation models. For
  hierarchical tables, use Panel's ``Tabulator`` widget. Bokeh-only
  applications can use ``DataTable`` with pre-aggregated data. See
  :ref:`ug_topics_hierarchical` for migration guidance.

* Removed the ``Arrow`` annotation model. Replace
  ``plot.add_layout(Arrow(x_start=..., y_start=..., x_end=..., y_end=...))``
  with ``renderer = plot.arrow(x_start=..., y_start=..., x_end=..., y_end=...)``.
  The returned ``GlyphRenderer`` draws decorated segments. Change shaft
  properties on ``renderer.glyph`` and head properties on its decorations.
  Existing ``OpenHead``, ``NormalHead``, ``VeeHead``, and ``TeeHead`` models
  remain available. Endpoints use data coordinates. Head sizes and decoration
  insets use screen pixels. See :ref:`ug_basic_annotations_arrows` for examples.

API changes
-----------

* Renamed ``GlyphRenderer.add_decoration()`` to
  ``GlyphRenderer.add_path_decoration()``. It takes a marking first and a
  keyword-only node: ``renderer.add_path_decoration(head, node="end")``. BokehJS uses
  ``renderer.add_path_decoration(head, {node: "end"})``.

* ``GlyphRenderer.add_path_markings()`` adds repeated fractional markings.
  Positions can be a shared list or a field containing one list per path.

* ``Decoration`` is an abstract base for decoration models. ``PathDecoration``
  attaches a marking to a named path node, and ``PathMarkings`` places markings
  at fractional path positions. These concrete models define their own marking
  and placement properties.

.. _release-4-0-0-validation:

Property validation and warning suppression
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Property validation overrides now belong to the current execution context.
Previously, overlapping ``validate(False)`` scopes could disable validation for
other sessions or leave it disabled permanently. Temporary ``silenced()`` scopes
are also context-local and preserve nested scopes and global ``silence()``
configuration.

A bare ``validate(False)`` in a server application's ``main.py`` no longer
disables validation for later callbacks running in separate contexts. Move the
override into the callback, using ``with validate(False):`` or
``@without_property_validation`` for synchronous callbacks:

.. code-block:: python

    from bokeh.core.properties import without_property_validation

    @without_property_validation
    def update():
        source.data = new_data()

To configure property validation for the entire process, use the new
:func:`~bokeh.core.properties.set_validation_default`:

.. code-block:: python

    from bokeh.core.properties import set_validation_default

    set_validation_default(False)

This default applies across threads and tasks, including contexts created
earlier, unless an explicit ``validate(...)`` override is active. Changes to
the default during an override take effect after the enclosing overrides exit.
Libraries assigning the private ``Property._should_validate`` attribute must
use ``set_validation_default()`` instead. Assigning that attribute now raises
an error with migration guidance.

Overrides propagate into new asyncio tasks and ``asyncio.to_thread``. They are
not copied by ``loop.run_in_executor`` or a user-managed ``ThreadPoolExecutor``.
``threading.Thread`` inheritance depends on Python's thread-context configuration;
do not assume propagation. Use ``contextvars.copy_context().run`` for explicit
propagation across these boundaries. These rules also apply to ``silenced()``;
use ``silence()`` for process-wide warning suppression.
